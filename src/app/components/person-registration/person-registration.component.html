🏢 How Enterprise Idempotency Works (Stripe & IETF Standard):

  1. Client Generates Key: Before making the request, a unique UUID is created and attached as Idempotency-Key: <UUID>.
  2. First Request: The backend computes a SHA-256 payload hash and atomically locks the key in SQL Server. It inserts the record into Persons and caches the response. Returns HTTP 201 Created.
  3. Duplicate Clicks / Network Retries: When another request arrives with the same key, the backend checks SQL Server. It detects the completed operation, verifies the payload hash, and replays the cached response with HTTP 200 OK and Idempotent-Replay: true header. No duplicate database insert ever occurs!
